# 算法计算细节

本文档对应 `stockapp/strategy.py`、`stockapp/portfolio.py`、`stockapp/market_data.py` 和 `stockapp/kronos_service.py` 的当前实现。它描述程序如何计算，不表示这些规则能够预测收益，也不构成投资意见。

## 1. 主流程

执行 `python -m stockapp.cli recommend` 后，程序按以下顺序运行：

1. 从 SQLite 读取沪深300指数最近最多 600 根日线。
2. 以指数最后一个交易日作为本次统一决策日。
3. 计算指数指标和 20 日收益。
4. 读取当前沪深300成分股及用户手工跟踪的 `active=1` 股票。
5. 每只股票读取最近最多 600 根日线，并删除决策日之后的数据。
6. 跳过历史不足、停牌、ST、关键指标缺失或最新日期不同步的股票。
7. 拼接决策日之前已经披露的结构化财务数字。
8. 在所有合格股票的同一截面上计算百分位和六组因子分。
9. 计算独立的机会分、风险分和数据完整度。
10. 用指数和成分股宽度计算市场分与市场状态。
11. 可选地对基础机会分排名靠前的股票执行 Kronos 推理并融合分数。
12. 先计算已有持仓的持有、减仓或退出状态。
13. 再从机会分前 `top_k` 名中生成关注或最多一个买入计划。
14. 将本次运行、全市场因子快照、风险倒排和操作结果写入 SQLite。

默认 `top_k=5`。Web 页面中的股票池来自最近一次完整的 `factor_snapshots`，不是临时在浏览器中计算。

## 2. 输入数据与时间截面

### 2.1 股票池

默认股票池来自 BaoStock 返回的当前沪深300成分股。用户在成交账本中录入沪深非成分股时，系统通过 BaoStock `query_stock_basic` 核对代码、证券类型和上市状态。验证成功后设置 `is_tracked=1`，后续增量同步和因子计算都会包含它：

```sql
SELECT code, name, industry, is_hs300
FROM securities
WHERE (is_hs300=1 OR is_tracked=1) AND active=1
ORDER BY code
```

新增的扩展股票在下一次 `sync` 前可能没有日线，此时会显示在股票池中，但不参与评分。市场宽度和市场状态始终只用 `is_hs300=1` 的行，扩展股票不会改变沪深300市场基准。

历史成分股快照虽然存入 `index_membership_snapshots`，但当前每日推荐没有使用历史成分股还原。它使用运行时的当前成分股及用户扩展集合。

### 2.2 日线字段

每根日线使用以下字段：

| 字段 | 含义 |
|---|---|
| `open/high/low/close` | 开高低收 |
| `volume` | 成交量 |
| `amount` | 成交额 |
| `turnover_rate` | 换手率 |
| `pe_ttm` | 滚动市盈率 |
| `pb_mrq` | 市净率 |
| `ps_ttm` | 滚动市销率 |
| `pcf_ncf_ttm` | 滚动市现率 |
| `trade_status` | 是否正常交易 |
| `is_st` | 是否 ST |

股票日线请求使用 BaoStock `adjustflag="2"`，指数使用 `adjustflag="3"`。同步采用 `(code, trade_date)` 唯一键执行插入或更新。

### 2.3 决策日

```text
决策日 = 沪深300指数缓存中的最后一个交易日
```

每只股票只保留 `trade_date <= 决策日` 的日线。股票最后一根日线必须恰好等于决策日，否则不进入当日评分。这避免某些股票数据已更新、另一些仍停留在前一天时混用截面。

### 2.4 历史长度和基础过滤

- 策略计算每只证券最多读取最近 600 根日线。
- 股票少于 120 根日线时跳过。
- `MA120`、`ATR14`、`RSI14`、`MACD histogram` 或 20 日波动率为空时跳过。
- 最新一根 `trade_status != 1` 时跳过。
- 最新一根 `is_st == 1` 时跳过。

K 线详情页读取数据库内该股票的全部历史，这与策略最多使用 600 根是两个独立行为。

### 2.5 财务数字的时间约束

财务表按数据类型分别选择：

```text
publish_date <= 决策日
且 report_period 为该数据类型在决策日前可见的最大报告期
```

字段写入因子表时增加数据类型前缀，例如 `profit_roeAvg`。当前同步的数据类型包括：

```text
profit, growth, operation, balance, cash_flow, dupont
```

当前财务质量分实际只读取其中 6 个字段，详见第 6.6 节。程序不读取财报正文。

## 3. 单股基础指标

以下公式都在按日期升序的日线上计算。`C_t`、`H_t`、`L_t`、`V_t`、`A_t` 分别表示第 `t` 日收盘、最高、最低、成交量和成交额。

### 3.1 均线与收益

```text
MA_n(t) = mean(C[t-n+1 ... t]), n ∈ {20, 60, 120}
return5(t)  = C_t / C_(t-5)  - 1
return20(t) = C_t / C_(t-20) - 1
MA20斜率5日 = MA20_t / MA20_(t-5) - 1
```

20 日相对强弱使用股票与沪深300同日 20 日收益之差：

```text
relative_strength20 = 股票return20 - 沪深300 return20
```

20 日突破基准排除当日：

```text
previous_high20(t) = max(C[t-20 ... t-1])
breakout20 = C_t >= previous_high20(t)
distance_ma20 = C_t / MA20_t - 1
```

### 3.2 ATR

```text
TR_t = max(
  H_t - L_t,
  abs(H_t - C_(t-1)),
  abs(L_t - C_(t-1))
)
ATR14_t = 最近14个TR的简单平均
atr_ratio = ATR14_t / C_t
```

这里使用简单移动平均，不是 Wilder 平滑 ATR。

### 3.3 成交量与成交额

```text
volume_median20(t) = median(V[t-20 ... t-1])
volume_ratio = V_t / volume_median20(t)

amount_mean5(t)  = mean(A[t-4 ... t])
amount_mean20(t) = mean(A[t-19 ... t])
amount_ratio5_20 = amount_mean5 / amount_mean20
```

成交量基准排除当日，成交额均值包含当日。

### 3.4 MACD

Pandas 使用 `adjust=False` 计算指数移动平均：

```text
EMA12 = EWM(close, span=12)
EMA26 = EWM(close, span=26)
MACD = EMA12 - EMA26
Signal = EWM(MACD, span=9)
Histogram = MACD - Signal
Histogram变化 = Histogram_t - Histogram_(t-1)
```

### 3.5 RSI14

```text
delta_t = C_t - C_(t-1)
gain14 = 最近14日 max(delta, 0) 的简单平均
loss14 = 最近14日 max(-delta, 0) 的简单平均
RS = gain14 / loss14
RSI14 = 100 - 100 / (1 + RS)
```

当除数为 0 或结果为空时，当前实现填充为 `50`。这里也不是 Wilder 平滑 RSI。

### 3.6 KDJ

```text
low9  = 最近9日最低价的最小值
high9 = 最近9日最高价的最大值
RSV = (C_t - low9) / (high9 - low9) * 100
K = EWM(RSV, com=2, adjust=False)
D = EWM(K,   com=2, adjust=False)
J = 3K - 2D
```

当前评分使用 `K > D`，计算了 `J` 但没有直接加入分数。

### 3.7 OBV 与涨跌成交量比

```text
direction_t = sign(C_t - C_(t-1))
OBV_t = 累计求和(direction_t * V_t)
OBV斜率10 = (OBV_t - OBV_(t-10)) / mean(V[t-19 ... t])

上涨成交量20 = sum(V_i, 当日收益 > 0)
下跌成交量20 = sum(V_i, 当日收益 < 0)
涨跌成交量比 = 上涨成交量20 / 下跌成交量20
```

下跌成交量为 0 时比值为空；进入原始因子表时用 `1.0` 代替。

### 3.8 MFI14

```text
典型价格 = (H + L + C) / 3
资金流 = 典型价格 * 成交量
正资金流14 = 典型价格上涨日资金流的14日和
负资金流14 = 典型价格下跌日资金流的14日和
资金比 = 正资金流14 / 负资金流14
MFI14 = 100 - 100 / (1 + 资金比)
```

无法计算时填充为 `50`。

### 3.9 波动、下行波动和回撤

```text
日收益 = C_t / C_(t-1) - 1
volatility20 = std(最近20日日收益) * sqrt(252)
downside_vol20 = std(最近20日 min(日收益, 0)) * sqrt(252)
drawdown20 = C_t / max(C[t-19 ... t]) - 1
```

下行波动计算把非负收益日记为 0，而不是从样本中删除。

### 3.10 Beta 与相关性

股票和指数按 `trade_date` 内连接，取最近 60 个共同交易日：

```text
beta60 = cov(股票日收益, 指数日收益) / var(指数日收益)
correlation60 = corr(股票日收益, 指数日收益)
```

共同样本少于 40 个或指数方差为 0 时，`beta60=1.0`。相关性无法计算时记为 `0.0`。相关性目前只保存，不直接参与评分。

## 4. 横截面百分位

许多指标不是用固定阈值评分，而是在当日所有合格股票中排名：

```text
正向百分位(x) = rank(x, pct=True, method="average") * 100
反向百分位(x) = 100 - 正向百分位(x)
```

数值越大越好的指标使用正向百分位；数值越小越好的指标使用反向百分位。并列值使用平均名次。因此分数表示当日股票池中的相对位置，不是上涨概率，也不保证不同日期的绝对可比性。

## 5. 六组因子分

### 5.1 趋势分 `trend_score`

每个条件满足就获得固定分数，总分范围 0 到 100：

| 条件 | 分数 |
|---|---:|
| 收盘价 > MA20 | 20 |
| MA20 > MA60 | 20 |
| MA60 > MA120 | 15 |
| MA20 的 5 日斜率 > 0 | 15 |
| MACD > Signal | 15 |
| MACD Histogram 较前一日增加 | 10 |
| 收盘价达到或突破前 20 日最高收盘 | 5 |

### 5.2 动量分 `momentum_score`

先计算两个子分：

```text
RSI质量 = clip(100 - abs(RSI14 - 60) * 2, 0, 100)
KDJ时点 = 100 if K > D else 0
```

再合成：

```text
动量分 = 20日相对强弱百分位 * 55%
       + RSI质量              * 30%
       + KDJ时点              * 15%
```

RSI 在 60 时得 100 分；偏离 60 越远，得分越低。

### 5.3 量价分 `volume_score`

```text
MFI质量 = clip(100 - abs(MFI14 - 60) * 2, 0, 100)

量价分 = 当日量比百分位       * 20%
       + 20日平均成交额百分位 * 20%
       + OBV斜率百分位        * 25%
       + MFI质量              * 20%
       + 涨跌成交量比百分位   * 15%
```

### 5.4 波动质量分 `volatility_score`

```text
波动率质量 = volatility20 的反向百分位
ATR质量 = clip(100 - abs(atr_ratio - 0.025) * 2500, 0, 100)
Beta质量 = clip(100 - abs(beta60 - 1) * 50, 0, 100)

波动质量分 = 波动率质量 * 45%
           + ATR质量    * 35%
           + Beta质量   * 20%
```

ATR 占价格 2.5% 时 ATR 子分最高。Beta 越接近 1，Beta 子分越高。该组偏好较低总体波动、适中的 ATR 和接近市场的 Beta。

### 5.5 估值分 `valuation_score`

分别对正数 `PE/PB/PS/PCF` 做行业内反向百分位，数值越低得分越高：

```text
估值分 = mean(PE行业分, PB行业分, PS行业分, PCF行业分)
```

具体边界：

- 估值值 `<= 0` 先视为缺失，不参与排名。
- 行业内有效样本规模不足 4 时退回全市场百分位。
- 最终仍缺失的单项填 `20` 分。
- 行业使用 `securities` 中当前行业，不做历史行业还原。

### 5.6 财务质量分 `quality_score`

对存在的项目先变换到 0 到 100，再对可用项目做简单平均：

```text
ROE分       = clip(roeAvg / 0.20 * 100, 0, 100)
净利率分    = clip(50 + npMargin * 100, 0, 100)
净利润增长分 = clip(50 + YOYNI * 100, 0, 100)
归母净利增长分 = clip(50 + YOYPNI * 100, 0, 100)
经营现金质量分 = clip(CFOToNP * 80, 0, 100)
负债率分    = clip(100 - liabilityToAsset * 100, 0, 100)

财务质量分 = 上述可用子分的算术平均
```

对应数据库键：

```text
profit_roeAvg
profit_npMargin
growth_YOYNI
growth_YOYPNI
cash_flow_CFOToNP
balance_liabilityToAsset
```

六项全部缺失时，财务质量分固定为 `50`。程序直接使用数据源保存的数值单位，不做额外百分数换算。

## 6. 机会分

六组原始权重之和为 90%，程序除以 `0.90` 将其归一化到 100 分：

```text
机会基础分 = (
    趋势分     * 20%
  + 动量分     * 15%
  + 量价分     * 20%
  + 波动质量分 * 10%
  + 估值分     * 10%
  + 财务质量分 * 15%
) / 0.90
```

未启用 Kronos 时：

```text
opportunity_score = opportunity_base
```

页面的“推荐理由”只展示六组中得分最高的三组；它不是全部计算依据。

## 7. 风险分

风险分独立计算，不是 `100 - 机会分`。先构造六个风险组：

### 7.1 趋势破坏风险，权重 25%

```text
趋势破坏原始分 =
    (收盘 < MA20)          * 35
  + (MA20 < MA60)          * 30
  + (MACD Histogram < 0)   * 20
  + (Histogram变化 < 0)    * 15
```

### 7.2 下行与回撤风险，权重 20%

```text
下行风险分 = 下行波动率正向百分位 * 55%
           + (-drawdown20)百分位  * 45%
```

回撤越深，`-drawdown20` 越大，风险百分位越高。

### 7.3 量价派发风险，权重 20%

```text
量价派发分 = (-OBV斜率)百分位       * 40%
           + (-涨跌成交量比)百分位 * 35%
           + (100 - MFI质量)       * 25%
```

### 7.4 流动性衰减风险，权重 15%

```text
流动性衰减分 = 100 - amount_ratio5_20 的正向百分位
```

近 5 日相对 20 日成交额越弱，风险越高。

### 7.5 财务与估值风险，各 10%

```text
财务风险 = 100 - 财务质量分
估值风险 = 100 - 估值分
```

### 7.6 最终风险分

```text
risk_score_base = clip(
    趋势破坏原始分 * 25%
  + 下行风险分     * 20%
  + 量价派发分     * 20%
  + 流动性衰减分   * 15%
  + 财务风险       * 10%
  + 估值风险       * 10%,
  0, 100
)
```

风险榜按风险分从高到低取 `top_k`。风险分 `>=65` 标记 `HIGH_RISK`，否则标记 `CAUTION`。即使当日最高风险低于 65，风险榜仍会显示倒排前 `top_k`，但标签是“需谨慎”。

风险原因最多展示四条，按以下顺序检查：跌破 MA20、MA20 低于 MA60、MACD 负向加速、20 日回撤低于 -8%、成交额比低于 0.65、OBV 下行、PE 非正、净利润同比下降超过 20%、Kronos 预测低于 -2%。原因文字是解释摘要，不参与额外加分。

## 8. 数据完整度 `confidence`

纯因子版本从 60 分开始：

```text
confidence = 60
           + 换手率存在 ? 5 : 0
           + 四项估值字段非空比例 * 15
           + 财务字段非空比例     * 15
```

其中财务字段指列名前缀为 `profit_`、`growth_`、`cash_flow_`、`balance_` 的全部已拼接列。纯因子结果最终限制在 `[0, 95]`。

该分数表示输入字段覆盖程度，不是预测置信概率，不表示有对应概率上涨。

## 9. 市场分与市场状态

### 9.1 成分股宽度

在当日所有合格股票中计算：

```text
above20 = 收盘 > MA20 的股票比例
above60 = 收盘 > MA60 的股票比例
positive20 = return20 > 0 的股票比例
breakout_breadth = breakout20 为真的股票比例
```

### 9.2 市场分

```text
市场分 =
    (指数收盘 > 指数MA20)  ? 10 : 0
  + (指数收盘 > 指数MA60)  ? 10 : 0
  + (指数收盘 > 指数MA120) ? 15 : 0
  + (指数MA20 > 指数MA60)  ? 10 : 0
  + above20          * 15
  + above60          * 10
  + positive20       * 10
  + breakout_breadth * 5
  + clip((0.30 - 指数volatility20) / 0.20 * 10, 0, 10)
  + clip(指数amount_ratio5_20 * 2.5, 0, 5)

市场分 = clip(市场分, 0, 100)
```

### 9.3 状态阈值

```text
市场分 >= 65       -> RISK_ON，允许评估新开仓
50 <= 市场分 < 65  -> CAUTIOUS，不开新仓
市场分 < 50        -> RISK_OFF，不开新仓
```

`market_state()` 还计算了一套基础布尔状态，但主流程最终使用上述增强市场分覆盖其状态结果。

## 10. Kronos 融合

只有同时满足以下条件才尝试模型：

- 命令传入 `--kronos` 或 Web 勾选 Kronos。
- Kronos 源码、模型目录和 tokenizer 目录都存在。
- `KRONOS_ENABLED` 没有显式关闭。

程序先按机会基础分排序，只对前 `max(top_k*2, 10)` 只执行推理。默认 `top_k=5`，因此默认最多推理 10 只。

### 10.1 模型输入输出

每只股票输入最近 512 根：

```text
open, high, low, close, volume, amount
```

模型预测未来 5 个工作日。当前推理参数为：

```text
T=1.0, top_k=1, top_p=1.0, sample_count=1
```

从结果提取：

```text
kronos_return = 第5日预测收盘 / 最后真实收盘 - 1
kronos_path_low = 预测5日最低价最小值 / 最后真实收盘 - 1
kronos_score = clip(50 + kronos_return / 0.05 * 50, 0, 100)
kronos_risk  = clip(50 - kronos_return / 0.05 * 50, 0, 100)
```

这意味着预测收益 `+5%` 对应模型机会分 100，`0%` 对应 50，`-5%` 对应 0。风险映射方向相反。`kronos_path_low` 会保存，但当前不进入风险分公式。

### 10.2 融合

```text
最终机会分 = 机会基础分 * 90% + kronos_score * 10%
最终风险分 = 风险基础分 * 90% + kronos_risk  * 10%
完整度 = min(100, 原完整度 + 5)
```

单只股票推理失败时记录 `kronos_error`，该股票保留纯因子分。模型整体初始化失败或模型不可用时，整次运行退回纯因子算法，不阻止报告生成。

### 10.3 预测缓存与单股计算

每次成功推理会把汇总值和未来 5 根完整预测 K 线写入 `kronos_predictions`。缓存键由以下字段组成：

```text
股票代码 + 最后真实交易日 + 预测周期 + 模型目录标识
```

缓存内容包括：

```text
kronos_return, kronos_path_low, kronos_score
未来每日 open/high/low/close/volume/amount
```

批量策略对候选股票推理前先查询缓存。缓存键完全匹配时直接复用，不加载模型；行情更新到新的交易日或模型目录改变后，旧缓存不会用于新的预测。

个股详情页在当前真实日线至少有 512 根、模型可用且当前交易日没有缓存时显示“计算Kronos预测”按钮。计算成功后保存缓存，并用独立颜色的预测蜡烛显示未来区间。

单股按钮不会修改已经生成的 `factor_snapshots`、机会分或风险分。后续运行全市场策略时，如果该股票进入需要 Kronos 处理的候选范围，同日缓存会被复用并按第 10.2 节参与融合。

## 11. 新开仓判断

### 11.1 账户级开仓开关

以下条件必须全部满足：

```text
市场状态 == RISK_ON
账户回撤 > -5%
当前持仓数量 < 3
当前总仓位 < 60%
```

账户回撤和总仓位见第 13 节。

### 11.2 单股资格

程序只检查最终机会分前 `top_k` 名。单股必须全部满足：

```text
5 <= 最新收盘价 <= 100
20日平均成交额 >= 500,000,000
机会分 >= 72
风险分 <= 35
完整度 >= 70
```

满足账户和单股条件后才计算股数。一天最多把一只股票标记为 `BUY`；其余前 `top_k` 股票标记为 `WATCH`。排名靠前但不满足阈值的股票也只是 `WATCH`，程序会继续检查后续名次是否满足买入条件。

计划参考区间只是最新收盘价的固定比例：

```text
price_low  = 最新收盘 * 0.985
price_high = 最新收盘 * 1.02
```

程序不连接券商，不读取盘中实时价格，也不会自动下单。

## 12. 仓位和初始止损

```text
止损距离 = min(2 * ATR14, 计划价 * 6%)
单笔风险预算 = 账户权益 * 0.5%
风险约束股数 = floor(单笔风险预算 / 止损距离 / 100) * 100
单股仓位上限 = 账户权益 * 20%
仓位约束股数 = floor(单股仓位上限 / 计划价 / 100) * 100
计划股数 = max(0, min(风险约束股数, 仓位约束股数))
初始止损价 = 计划价 - 止损距离
```

股数向下取整为 100 股整数倍。若结果不足 100 股，则保持 `WATCH`，不生成 `BUY`。

示例：账户权益 50,000 元，计划价 20 元，ATR14 为 0.50 元：

```text
止损距离 = min(1.00, 1.20) = 1.00
风险预算 = 50,000 * 0.5% = 250
风险约束股数 = floor(250 / 1 / 100) * 100 = 200
仓位约束股数 = floor(10,000 / 20 / 100) * 100 = 500
计划股数 = 200
初始止损 = 19.00
```

该计算未额外预留买入手续费，也没有检查当前现金是否足以覆盖新计划；账户总仓位和单股权益上限是主要约束。

## 13. 账户计算

成交按日期和记录 ID 顺序回放。

### 13.1 买入

```text
新平均成本 = (原持仓数量 * 原平均成本 + 买入数量 * 成交价 + 手续费)
             / 新持仓数量
现金减少 = 买入数量 * 成交价 + 手续费
```

从空仓首次买入时创建 `position_controls`，保存建仓日、初始止损、当前止损和最高收盘。

### 13.2 卖出

```text
已实现盈亏增加 = (卖出价 - 平均成本) * 卖出数量 - 手续费
现金增加 = 卖出数量 * 卖出价 - 手续费
```

部分卖出不改变剩余持仓平均成本；全部卖完后平均成本归零，并删除该股票的持仓控制记录。

### 13.3 权益、仓位和回撤

持仓使用数据库中该股票最新收盘价估值；缺少行情时退回平均成本：

```text
持仓市值 = 数量 * 最新价
账户权益 = 现金 + 持仓市值
总仓位 = 持仓市值 / 账户权益
未实现盈亏 = 持仓市值 - 数量 * 平均成本
峰值权益 = max(已保存峰值权益, 当前权益)
账户回撤 = 当前权益 / 峰值权益 - 1
```

策略运行结束前会把最新峰值权益写回 `settings`。只打开页面计算账户时，不单独持久化新峰值。

## 14. 已有持仓的操作优先级

每只持仓按以下顺序判断，一旦命中就不再检查后面的退出条件：

1. 当前止损存在且最新收盘 `<= 当前止损`：`SELL` 全部持仓。
2. 连续两个交易日收盘都低于各自 MA20：`SELL` 全部持仓。
3. 市场为 `RISK_OFF` 且个股最新收盘低于 MA20：`SELL` 全部持仓。
4. 达到 2R 且尚未标记已经减仓：`REDUCE`。
5. 其他情况：`HOLD`。

其中：

```text
持仓收益率 = 最新收盘 / 平均成本 - 1
初始每股风险R = 平均成本 - 初始止损
达到2R条件 = 持仓收益率 >= 2 * 初始每股风险R / 平均成本
```

达到 2R 后，无论当次显示 `REDUCE` 还是后续 `HOLD`，都会更新：

```text
历史最高收盘 = max(已保存最高收盘, 最新收盘)
ATR移动止损 = 历史最高收盘 - 2 * ATR14
当前止损 = max(旧当前止损或0, 平均成本, ATR移动止损)
```

减仓数量：

```text
REDUCE数量 = floor(当前持仓数量 / 200) * 100
```

例如 500 股减 200 股，300 股减 100 股，100 股会得到 0 股。`SELL` 数量等于全部持仓数量。

当前实现会读取 `partial_taken` 防止重复 2R 减仓，但录入部分卖出时尚未自动把该字段更新为 1。因此仅按现有代码操作时，满足 2R 的持仓可能在后续运行再次出现 `REDUCE`。这是当前实现限制，不应把它理解为有意的多级止盈规则。

## 15. 报告输出与数据库落表

每次成功运行生成一个 `recommendation_runs` 记录，并写入：

- `factor_snapshots`：每只合格股票的机会分、风险分、完整度、六组分和全部指标。
- `kronos_predictions`：按股票、真实数据截止日、周期和模型标识保存的模型预测及未来 K 线。
- `risk_alerts`：风险分最高的 `top_k` 只股票及原因。
- `recommendations`：已有持仓的操作结果，加上机会分前 `top_k` 的 `BUY/WATCH` 结果。

盘前总消息按优先级生成：

1. 任一持仓为 `SELL/REDUCE`：`优先处理持仓风险`。
2. 当日生成买入计划：`一只股票满足完整买入条件`。
3. 市场为 `RISK_OFF`：`市场风险较高，今日不开新仓`。
4. 市场为 `CAUTIOUS`：`市场环境偏谨慎，今日不开新仓`。
5. 其他情况：`暂无完整买入信号，今日不操作`。

## 16. 当前未进入主流程的旧评分函数

`strategy.py` 中仍保留 `candidate_metrics()`、`reasons_for()` 和一套 `technical_score/full_signal` 规则。当前 `run_strategy()` 没有调用它们；每日报告使用的是本文第 3 至 15 节描述的全市场因子路径。

因此：

- `technical_score` 不会与当前机会分相加。
- 旧 `full_signal` 不决定当前 `BUY`。
- 修改旧函数不会改变当前推荐结果，除非主流程重新接入它们。

## 17. 重要边界

- 所有分数都依赖缓存数据质量和当日合格股票集合。
- 百分位是相对排名，股票自身指标不变时也可能因其他股票变化而改变。
- 当前策略不是盘中策略；使用完整日线收盘数据生成下一次查看的报告。
- 估值和财务数据可能为空、滞后或单位异常，完整度只衡量覆盖，不验证真实性。
- 当前推荐没有使用新闻、公告正文、舆情或人工判断。
- 当前代码没有实现历史回测撮合、滑点、涨跌停成交限制、停牌后的执行模拟或税费模型。
- `BUY/WATCH/SELL/REDUCE` 是规则计算标签，不是软件代替用户作出的交易决定。
